# Benchmarks

这些数据来自开发阶段，目的是让优化结果可以复现，而不是承诺所有手机、
屏幕和页面都获得完全相同的耗时。

## 环境

- 设备：Android 模拟器，Pixel 3a API 35，x86_64
- 应用：InkReader 0.3.9
- 屏幕协议：552 × 768 二色/四色帧布局
- 压测小说：原创生成文本，32,564,033 字节，6200 章
- 压缩验证：MIT 许可的独立 `lzokay` 解码器

## D3 包数与压缩量

整页打包后为 105,984 字节，客户端按 2 KiB 原始块压缩。每个 D3 APDU
最多携带 250 字节压缩数据。

```text
旧字面量流：476 个 D3 包
当前 LZO1X：55 个 D3 包
53 个 2 KiB 块的理论下限：53 个 D3 包
包数减少：(476 - 55) / 476 = 88.4%
负载减少：(106620 - 7795) / 106620 = 92.7%
```

纯白 2 KiB 块从 2,012 字节降至 19 字节，减少约 99.1%。同一帧的全部
压缩块只计算一次并缓存，发送时不会重复压缩。

运行诊断：

```powershell
python tests\run_tests.py
java -cp build\tests-<id> org.nfcresearch.qpolllab.PacketCountProbe <packed-frame.bin>
```

压缩器另外通过了 2005 个覆盖 1–2000 字节的独立解码样本。

## 翻页参数

预传命中时：

- D4 上电等待：`2000 ms -> 500 ms`，减少 75%
- DE 忙闲查询间隔：`500 ms -> 50 ms`，减少 90%
- D3 上传：跳过

预传未命中时仍会退回完整 D3 + D4，并使用更保守的 2000 ms 上电等待，
优先保证画面完整。

包数和参数是确定的；最终翻页时间仍取决于 NFC 往返和屏幕自身刷新周期，
不能把参数降低比例直接等同于整次翻页的耗时比例。

## APK 与内存

同一测试环境下的 0.3.9：

```text
APK：120,081 字节（约 117 KiB）
冷启动：690 ms
书架 PSS：23,676 KiB
阅读页 PSS：51,459 KiB
```

PSS 来自 `adb shell dumpsys meminfo`，不代表所有书籍和系统版本的最大值。

## 大文件

压测文件使用 32,564,033 字节、6200 章的原创文本：

- 流式导入，无 ANR；
- 目录初始读取 100 章，滚动继续加载；
- 阅读时只解码当前章节块；
- 文件超过 32 MiB 时，即使内容提供方不返回文件大小，读取流也会主动终止。
